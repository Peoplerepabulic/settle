# Settle 🍽️

**The friend who actually makes the plan.** Settle is an AI agent that lives
in your iMessage group chats and turns "where should we eat??" chaos into a
decision — collecting preferences, proposing real options, running the vote,
breaking ties, surviving vetoes, and remembering what your crew likes.

Built for **HackWashU × Photon** ("Agents in iMessage" track) on
[Photon Spectrum](https://photon.codes/docs/spectrum-ts/introduction)
(`spectrum-ts`).

---

## 2-minute demo script (for judges)

1. **Add Settle to a group chat** and type `@Settle help us pick a dinner spot for Friday`.
2. **Answer one question** — cuisine, budget, area ("ramen, not too pricey, near campus").
3. **Settle proposes 4 concrete options.** Everyone votes with a number (`2`)
   or a 1️⃣–4️⃣ reaction on the options message.
4. **Watch it handle the hard parts:** a 3-way tie triggers an instant
   runoff; the winner faces a veto round (`veto` drops it and re-runs the
   vote); silence locks it in with 🎉.
5. **It remembers** — next time, Settle already knows this crew likes ramen.

No iMessage handy? The scripted run-through is in [`demo/transcript.md`](demo/transcript.md),
generated by driving the real decision engine.

## How it works

```
iMessage group chat
       │  (Photon cloud provider — persistent gRPC stream, no webhooks)
       ▼
  Spectrum app.messages ──► agent.ts ──► decision.ts (state machine)
       ▲                                     │  ├─ llm.ts (intent, constraints,
  space.send / reply / react                  │  │   candidates — JSON mode)
  (typing indicators, threads, tapbacks)      │  └─ keyword fallbacks (no key needed)
                                              ▼
                                         memory.ts ──► data/memory.json
                                         (roster, preferences, history)
```

**Decision state machine** (one session per space):

```
idle → collecting → voting → veto → decided
                  ↘ tie → instant runoff → voting
```

- **collecting** — extracts cuisine / budget / location / dietary / when via
  LLM (JSON mode) or keyword heuristics; proposes as soon as there's enough.
- **voting** — votes by number or 1️⃣–4️⃣ reactions; change votes freely;
  auto-tallies when everyone has voted; inactivity auto-tallies too.
- **tie** — instant runoff among the tied leaders, same numbers.
- **veto** — "any vetoes?" window (default 60s): a veto drops the winner and
  re-runs the vote; "no veto" / silence locks it in.
- **decided** — announced with flair; winner traits folded into the group's
  persistent preferences.
- `@Settle cancel` (or `cancel` mid-flow) scraps the session. Late joiners
  just vote — they're folded in automatically.

## Setup

### 1. Photon dashboard (for the real iMessage agent)

1. Sign up at the Photon dashboard and use promo code **`HACKWITHPHOTON`**
   for a free month of Pro.
2. Connect an iMessage line through the dashboard and copy your
   **Project ID** and **Project Secret**.

### 2. Run it

```bash
npm install
cp .env.example .env        # fill in SPECTRUM_PROJECT_ID / SPECTRUM_PROJECT_SECRET
                            # and (recommended) LLM_API_KEY
npm run dev                 # tsx src/index.ts
```

Add the connected iMessage number to any group chat and start debating.

### 3. Terminal demo mode (no credentials)

```bash
PROVIDER=terminal npm run dev
```

A local CLI chat with the same engine — perfect for rehearsing the demo or
developing without touching iMessage. Without `LLM_API_KEY`, Settle uses
built-in keyword heuristics so the whole flow still works.

### 4. Deploy

Needs a long-lived Node.js (≥20) or Bun runtime — Spectrum holds a
persistent connection to Photon, so serverless functions won't work. Any
always-on host works (Railway, Render, Fly.io, a VPS):

```bash
npm run build && npm start   # runs dist/index.js
```

Set the env vars from `.env.example` on the host. That's it — no public URL,
no webhook tunnel.

## Configuration

| Var | Default | What |
|---|---|---|
| `PROVIDER` | `imessage` | `imessage` or `terminal` |
| `SPECTRUM_PROJECT_ID` / `SPECTRUM_PROJECT_SECRET` | — | From the Photon dashboard |
| `LLM_API_KEY` | — | Any OpenAI-compatible key (optional; heuristics kick in without it) |
| `LLM_BASE_URL` | `https://api.openai.com/v1` | Override for other providers |
| `LLM_MODEL` | `gpt-4o-mini` | Any chat model with JSON mode |
| `VETO_WINDOW_MS` | `60000` | "Any vetoes?" window |
| `TALLY_TIMEOUT_MS` | `600000` | Inactivity before auto-tally |

## File tree

```
├── src/
│   ├── index.ts     # composition: provider switch (imessage/terminal), env, startup
│   ├── agent.ts     # Spectrum message loop, onboarding, send helpers
│   │                # (typing indicators, threaded replies, best-effort reactions)
│   ├── decision.ts  # per-space decision state machine + vote/veto/runoff logic
│   ├── llm.ts       # OpenAI-compatible chat wrapper (JSON mode) + prompts
│   └── memory.ts    # per-space roster, learned preferences, decision history
├── data/            # memory.json lives here at runtime (gitignored)
├── demo/
│   └── transcript.md# scripted full-flow demo (collect → vote → tie → runoff → veto → decided)
├── package.json / tsconfig.json / .env.example
```

## Stretch goals (not built — deliberately)

- **Google Places API** for real restaurant data (hours, ratings, maps links)
  instead of LLM-suggested spots.
- **Calendar reminders** — "dinner Friday 7pm" → event + nudge.
- **Polls API** for native iMessage polls; **multi-agent** (one agent per
  friend negotiating).
- Smarter memory: per-person taste profiles, "you always veto sushi" callouts.
